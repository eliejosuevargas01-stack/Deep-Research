## Implementation Integrity Verdict

**Pass (with drift).** The surface is recognizably this product, not a generic dashboard: flat suggestion rows instead of box-in-box cards, a real sidebar with `aria-current`, an execution workspace that separates the reasoning feed from a status column, and copy written for research work ("pontos aprovados", "auditoria do ciclo"). The mechanics that usually signal slop are present and correct: `sr-only` live regions, disclosure `aria-expanded`/`aria-controls`, `aria-invalid`+`aria-describedby` on form errors, `aria-current="step"` on pipeline stages, and a `prefers-reduced-motion` block that removes movement without killing feedback.

The drift is architectural, not stylistic: a second and third palette layer (`--clean-*` literals in `clean-theme.css`, `--oc-*` in `open-canvas.css`) sits under the `--color-*` token layer and never switches theme. `.app-shell` paints `--clean-canvas` (`#fafafc`) while text resolves `--ink` (`#F8FAFC`), which is why dark mode is unreadable rather than merely unpolished.

## Findings

### P1 — Major

**[P1] Dark theme leaves light surfaces with light text**
Location: `src/styles/clean-theme.css:6,19` (`--clean-canvas: #fafafc`; `.app-shell { background: var(--clean-canvas) }`), `src/styles/tokens.css:126` (`:root[data-theme='dark']`).
Measured with `data-theme="dark"`: `.app-shell` background `rgb(250,250,252)`; `h1.empty-state-title` `#F8FAFC` on `rgb(250,250,252)` = **1.0:1**; `p.empty-state-text` 1.18; `b` brand "Research" 2.57; `.sidebar-item` inactive `#475569` on `#1E293B` 1.93; `.card-title` in Settings and Execution 1.0. The sidebar and the composer switch correctly, the canvas does not — the result is a half-themed screen.
Impact: the theme toggle produces an unreadable app; users who pick dark mode must switch back.
Standard: WCAG 1.4.3 (AA).
Recommendation: make `--clean-canvas`, `--clean-ink`, `--clean-body`, `--clean-muted`, `--clean-line` alias the `--color-*` tokens (or delete the layer), and set `--clean-*` inside `:root[data-theme='dark']`. Verify by reading computed background of `body`, `.app-shell` and every card under dark.

**[P1] Muted text token fails AA on always-visible labels**
Location: `src/styles/clean-theme.css:11,103-109,162` (`--clean-muted: #94a3b8`), `src/styles/open-canvas.css:8,101-104` (`--oc-muted`), `src/styles/components.css:1722` (`.form-label-hint` → `--color-text-muted`, dark value leaks into light surfaces where `#94A3B8` is used).
Measured: `p.sidebar-group` "Investigação"/"Sistema" 10.5 px = **2.56:1**, `span.sidebar-footer-note` 11 px = 2.56:1, `span.form-label-hint` 11.5 px = **2.46:1** (13 instances on `#settings`), `span.reasoning-tab-count` 11 px = 2.46:1.
Impact: section labels and field hints are the navigation and the form's only explanation; they are the least legible text on the page.
Standard: WCAG 1.4.3 (AA, 4.5:1).
Recommendation: use the documented `text-muted` `#6B7280` (4.83:1) — DESIGN.md already specifies it, so this is drift, not a new decision.

**[P1] Keyboard focus is invisible on the mobile sample-topic rows**
Location: `src/styles/main.css:48` (`:focus-visible { box-shadow: var(--focus-ring) }`), overridden by `src/styles/clean-theme.css:610-617` (`.sample-topic-card { box-shadow: none }`, same specificity, later sheet).
Measured at 390 px with real `Tab` presses: `box-shadow: none`, `outline-style: none` on all three `.sample-topic-card` buttons. Every other control shows `0 0 0 2px #FFFFFF, 0 0 0 4px #7C3AED`.
Impact: keyboard users cannot see which suggestion will be submitted.
Standard: WCAG 2.4.7 (AA).
Recommendation: scope the reset to `.sample-topic-card:not(:focus-visible)` or re-declare `:focus-visible` after it.

**[P1] Layout clips below 375 px, hidden by `overflow-x: clip`**
Location: `src/styles/clean-theme.css:650-653` (`grid-template-columns: minmax(220px, 38%) 1fr; gap: 18px`), `src/styles/main.css:43` (`overflow-x: clip`).
Measured: at 320 px viewport `.app-shell` scrollWidth **362** vs 320, `section.empty-state` 346 vs 288, `li.sample-topic-item` 323 vs 288; at 360 px the same blocks overflow by 18 px. `documentElement.scrollWidth` stays clean because the root clips — the page-level check never reports it.
Impact: right-hand text and the `→` affordance are cut off on 320 px phones.
Standard: WCAG 1.4.10 (Reflow).
Recommendation: replace the fixed 220 px minimum with `minmax(0, 1fr)` plus `min-width: 0` on the grid children below 420 px, as already done for the workspace grid at ≤1080 px.

### P2 — Minor

**[P2] Reasoning toolbar overflows its card at ≤390 px**
Location: `src/styles/open-canvas.css:72-77` (`.reasoning-filter-row { display:flex; gap:18px }`, no wrap, no scroll), `src/styles/reasoning-feed.css:121-131`.
Measured: bar 358 wide, scrollWidth **368**; in `#harness` 310 wide, scrollWidth **374** (64 px clipped).
Recommendation: `flex-wrap: wrap` or give the row `overflow-x: auto` with `scrollbar-width: none`.

**[P2] Sample-topic description escapes the card on mobile**
Location: `src/styles/clean-theme.css:532-560` (`.sample-topic-title { flex: 0 0 38% }`, `.sample-topic-desc { flex: 1 1 auto }`).
Measured at 390 px: card right edge 335, `.sample-topic-desc` right edge **362** (27 px outside), second card 340.
Recommendation: `min-width: 0` on both children and allow the description to wrap/line-clamp.

**[P2] 200% text zoom breaks Settings**
Measured with root `font-size: 200%` at 1280: `.app-shell` scrollWidth **1503** vs 1280, `.settings-container` 1235 vs 988. Research route survives (page 1220 tall, no overflow).
Recommendation: replace fixed grid minimums in `.settings-container` with `minmax(0, 1fr)` and let label/value rows wrap.

**[P2] Progress bars animate `width`**
Location: `src/styles/open-canvas.css:721` (`transition: width 400ms ease`), `src/styles/planning-view.css:68` (`width 600ms ease`).
Impact: every progress tick triggers layout on two bars inside the streaming screen.
Recommendation: `transform: scaleX()` with `transform-origin: left` and `will-change: transform`.

**[P2] Font payload ships unused scripts**
Location: `src/styles/main.css:2-9` (`@fontsource/*` CSS imports). `dist/assets`: **72 font files, 1,001,004 bytes**, including `inter-cyrillic-*`, `inter-greek-*`, `inter-vietnamese-*`, `jetbrains-mono-cyrillic-*` — the interface is `pt-BR` only.
Recommendation: import the `latin`/`latin-ext` subsets only (`@fontsource/inter/latin-400.css` etc.).

**[P2] Single 172 KB gz JS chunk, no code splitting**
Measured `dist/assets/index-*.js` 552,393 B raw / **172,350 B gzip**; CSS 132,954 B / 33,237 B gzip. `gsap` (`src/App.tsx:2`) and `react-markdown`/`remark-gfm` (`ReportView`) load on the empty research screen.
Recommendation: `React.lazy` the report renderer and the docs view; GSAP usage is two tweens (`App.tsx:508,573`) and can be a CSS transition.

**[P2] Skip link is not the first focusable element on desktop**
Location: `src/App.tsx:943` (`<Sidebar>`) before `src/App.tsx:956` (`<a className="skip-link">`).
Measured: desktop `Tab` order starts at `.sidebar-brand`, skip link arrives 8th; at 390 px (sidebar hidden) it is first.
Standard: WCAG 2.4.1.
Recommendation: render the skip link before the sidebar.

### P3 — Polish

- **[P3] Undersized functional text**: `.sidebar-group` 10.5 px, `.reasoning-tab-count` 11 px, `.form-label-hint` 11.5 px. `--oc-muted`/`--clean-muted` at `#94a3b8` compounds it (detector: `undersized-ui-text`, `tiny-text`).
- **[P3] Filter tabs are 14 px tall** (`src/styles/open-canvas.css:79-90`, `padding: 0`). The WCAG 2.5.8 spacing exception is satisfied (18 px gaps, no 24 px circle intersections), so this is comfort, not a violation; 44 px would be the mobile ideal.
- **[P3] Static document title** (`frontend/index.html:7`): `#history`, `#settings` and `#docs` keep the research title.
- **[P3] Duplicated CSS declarations**: `.sample-topic-card` declared five times (`clean-theme.css:504,610,638,650`), `transition: width` twice, **428 raw hex literals** across sheets (uppercase and lowercase variants of the same color).
- **[P3] Unused dependencies**: `@fontsource/geist-sans`, `@fontsource/geist-mono` in `package.json`, never imported.
- **[P3] Missing space in an `h2`**: execution panel renders "Última auditoria disponível1/2" (`ExecutionView.tsx`), which screen readers announce as one token.

## Positive findings

- No console errors on any audited route at 1440 or 390.
- Page-level and per-element overflow clean at 768/1024/1280/1440.
- Landmarks and headings correct: one `main`, one `h1`, no skipped levels; `lang="pt-BR"`.
- Every interactive control reached by `Tab` has an accessible name; no unlabeled inputs; zero `<img>` without `alt` (no images at all).
- Live regions are implemented: `aria-live="polite"` for status, `aria-live="off"` on the elapsed timer so seconds are not narrated.
- Focus ring token exists and works on all desktop nav/controls (`0 0 0 2px #FFFFFF, 0 0 0 4px #7C3AED`).
- `prefers-reduced-motion` removes spatial motion and infinite pulses while preserving state change.
- Default theme is explicitly light and ignores `prefers-color-scheme` — verified with `colorScheme: 'dark'` and empty storage (`body` = `rgb(249,250,251)`).
- No `backdrop-filter`, no blur, `will-change` absent; feed auto-scroll is rAF-batched.
- Execution workspace uses exactly one scroll container at 1440 (`reasoning-feed-stream`), page locked to viewport, no `sr-only`-excluded clipping found.
